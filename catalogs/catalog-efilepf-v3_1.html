Private foundations · release efilepf_v3_1

The NCCS 990-PF Efile database turns the Form 990-PF returns that private foundations file electronically with the IRS into 80 relational tables, one or more for each Part of the form and its attached statements. Every table is published for each tax year in two formats, CSV and Parquet.

About this release

Data sources and processing

The Taxpayer First Act of 2019 made electronic filing mandatory for Form 990-PF for tax years beginning after July 1, 2019, so recent waves cover nearly every private foundation; earlier years include only foundations that chose to e-file. NCCS builds the database from the XML files indexed by the Giving Tuesday 990 Data Commons, supplemented with returns the IRS e-file index lists but the Data Commons index never picked up (see the release notes below).

Each XML element (xpath) is assigned to a research variable and a table by the Master Concordance (concordance990), and the tables are built with the ef2 package. A table holds one Part of the form: either one row per filing (1:1), or several rows per filing for repeating groups such as officers, grants paid, or capital gains (1:M). Tables in Part 99 hold the statements foundations attach to the return (accounting fees, depreciation, other investments, and so on).

The database also carries the two tables shared by every e-filed return: the filing header (F9-P00-T00-HEADER) and the signature block (F9-P02-T00-SIGNATURE). Here they hold 990-PF filings only. F9_00_ORG_EXEMPT_TYPE in the header is empty for 990-PF returns.

Efile data are organized by tax year, the year in which the foundation’s fiscal year begins (TAX_PERIOD_BEGIN_DATE). The IRS releases returns in monthly batches, so the most recent tax year is always incomplete. Form 990-PF was renumbered in 2023 (Part VI became Part V, and so on); the tables follow the pre-2023 numbering, and the part titles below give both.

Every table carries the keys needed to join tables to each other and to the BMF: OBJECTID (OID- followed by 18 digits, one per filing), EIN2, and TAX_YEAR. One-to-many tables add TABLE_ID (TID-NNN-NNN-NNN, one per row). Every row also carries URL, a link to the source XML return.

R packages

  • ef2 Parses IRS 990 e-file XML into the relational tables published here.
  • concordance990 The Master Concordance: maps XML xpaths to variables and tables; holds the data dictionaries.
  • panel990 Downloads efile tables and builds longitudinal panels, with BMF fields attached.
  • fiscal Fiscal health accounting metrics from 990 data.
  • governance Governance scores for nonprofits from Part VI.
  • peopleparser Splits officer and director names into parts and infers gender.
  • titleclassifier Classifies officer titles into standard roles.

Table and file names

Table names follow the pattern FF-PPP-TTT-NAME, and each file appends the tax year: PF-P15-T01-SUPPLEMENTARY-INFO-GRANT-PAID-2023.parquet.

  • FF is the form: PF = Form 990-PF; F9 marks the two shared header tables.
  • PPP is the part: P01 = Part I, P02 = Part II, and so on. P00 is the heading and P99 holds attached statements.
  • TTT is the table: T00 holds the one-to-one fields of the part, and T01, T02, … are its one-to-many tables.

Each table-year is published as CSV (readable anywhere) and Parquet (smaller and much faster in R with arrow or duckdb; panel990 reads Parquet by default). Both files hold the same rows and columns. Table-years with no filings are omitted from the listings below.

Release notes

Changes from efilepf_v2_3 to efilepf_v3_1. Generated by ef2::write_release_notes() on 2026-10-09.

Notes

  • New filings. This release adds filings that the Giving Tuesday Data Commons (GTDC) index never listed. The IRS e-file index lists 184,165 such filings (990, 990-EZ and 990-PF; IRS batches 2025_09A, 2025_10A, the second half of 2026_05A, and 2026_08A). Their XML is re-hosted at https://nccs-efile.s3.us-east-1.amazonaws.com/xml2/v2_3_patch/<OBJECT_ID>_public.xml, with PATCH-INDEX-v2_3-2026-10-07.csv beside them. The build index combined the GTDC index of 2026-08-25 with that patch, one row per filing.
  • TY2025 is new: built from the combined index. Many TY2025 returns are not filed yet, so expect it to grow.
  • Labels follow concordance990 2.0.1 (commit 02de916). Relabelling moved some xpaths between tables; where the builders already selected those cells by xpath, the published tables are unchanged.
  • Keys. OBJECTID is OID- + 18 digits, and TABLE_ID is the fixed-width TID-NNN-NNN-NNN (EF2-17), in every table.
  • Record. dev/UPSTREAM-ISSUES.md (EF2-18) in the ef2 repository documents how this release was built and checked.
  • Also added: 5,298 GTDC-indexed 990-PF filings for TY2016-2019 that the September 2026 PF build missed.
  • Header table. The shared F9-P00-T00-HEADER gains F9_00_ORG_EXEMPT_TYPE, which is empty for 990-PF filings (it is derived from 990 and 990-EZ paths only).
  • multi_value variables are still joined with ; in filing order (EF2-13 fix 2); the concordance changed which variables are multi-valued (see below).

Available tables

Each table lists its files by tax year. The code below each table uses panelize() from panel990 to download a multi-year panel of the table with BMF organization fields (NTEE codes, geography, subsection) attached.

Anchor your code to a release. panelize() reads the current release (efile_version()) unless told otherwise, so the same code returns different data after the next release. For reproducible results, name the release explicitly:

panel <- 
  panelize( tables = "PF-P01-T00-REVENUE-EXPENSE",
            years = 2020:2024,
            source = data_source( version = "v3_1", form = "990PF" ),
            bmf = TRUE )

BMF fields come from the current NCCS master BMF. To fix those as well, save the BMF once and pass the data frame or file path to bmf =.
